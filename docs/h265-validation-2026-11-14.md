# FilmCraft H.265 독립 검증 — 2026-11-14

## 범위

기준 소스는 ArtCraft PR #6의 `0c712e78b42ff191164a8b4902ae6a078feebae9`다. Apple M1(8 CPU), RAM 16GiB, Rust/Cargo 1.99.1, 외부 FFmpeg/ffprobe 9.0.2에서 직접 실행했다. 원격 Windows/NVIDIA·Linux의 결과가 아니다.

제품 인코더·디코더 구현을 변경하지 않았다. 테스트 2개를 추가하고, 기존 속도 테스트의 슬라이스 수가 실제 출력 코드와 달랐던 부분을 수정했다. main에 동시에 병합된 오프라인 큐 PR #7은 그대로 보존했고 이 H.265 커밋에서는 수정하지 않았다. 로컬 미커밋 리뷰 수정은 반영 대상이 아니며, 배포·Netlify 접근 설정도 변경하지 않았다.

## libkvazaar 환경과 fuzz

시스템 FFmpeg에 libkvazaar가 없어 중단됐던 검사를 별도 오라클 환경에서 다시 실행했다. 새 fixture 폴더에서 5개 seed를 생성해 전체 truncation/header-bit 변이 검사 및 seed당 무작위 400회를 실행했다. `FILMCRAFT_REQUIRE_ORACLES=1`에서 스킵 없이 **libtest 1개 통과·실패 0·ignored 0, 31.78초**다. 5개 seed나 무작위 2000회를 각각 별도의 Rust 테스트 개수로 부풀리지 않는다.

원래 fuzz 소스와 단언·600초 deadline은 변경하지 않았다. [입력·실행 영수증](h265-fuzz-verification-2026-11-14.json)에 외부 실행 파일·원본 로그와 5개 seed의 SHA-256을 기록했다.

```sh
FILMCRAFT_FFMPEG=/absolute/hevc-test-oracle/bin/ffmpeg \
FILMCRAFT_FFPROBE=/absolute/hevc-test-oracle/bin/ffprobe \
FILMCRAFT_FIXTURES_DIR=/absolute/new-fuzz-fixtures \
FILMCRAFT_REQUIRE_ORACLES=1 FILMCRAFT_FUZZ_ITERS=400 FILMCRAFT_FUZZ_SEED=20771 \
cargo test --locked --release -p filmcraft-hevc --test fuzz_hostile -- --nocapture --test-threads=1
```

외부 오라클은 제품 코드에 복사·링크·번들하지 않는다. [FFmpeg 공식 libkvazaar 문서](https://ffmpeg.org/ffmpeg-codecs.html#libkvazaar)에 따라 별도 테스트 실행 파일을 준비했다. 시스템 FFmpeg는 교체하지 않는다.

### 테스트 전용 FFmpeg 구성

macOS에서 `brew install kvazaar pkgconf x265`로 외부 빌드 의존성을 준비했다. 공식 FFmpeg 9.0.2 tarball의 SHA-256은 `8c3850283eb25fa026482078a04051e0be17347b09ef81a0849bec15a96e002e`였다. 소스는 외부 오라클 빌드에만 사용했으며 구현 코드를 제품으로 가져오지 않았다.

다음 구성으로 `make -j2`, `make install`을 실행했다. `wrapped_avframe`은 lavfi의 testsrc2 입력 처리에 필요하다. 첫 최소 구성에는 이 디코더가 빠져 fixture 생성이 실패했으며 이를 추가해 환경을 수정했다. `pkgconf`도 필요하다.

```sh
./configure --prefix=/absolute/hevc-test-oracle \
  --disable-everything --disable-autodetect --disable-doc --disable-debug \
  --enable-gpl --enable-libx265 --enable-libkvazaar --enable-ffmpeg --enable-ffprobe \
  --enable-encoder=libx265,libkvazaar,rawvideo,wrapped_avframe \
  --enable-decoder=hevc,rawvideo,wrapped_avframe \
  --enable-demuxer=hevc,rawvideo --enable-muxer=hevc,rawvideo,null \
  --enable-protocol=file,pipe --enable-indev=lavfi \
  --enable-filter=testsrc2,format,scale,null,buffer,buffersink \
  --enable-parser=hevc --enable-swscale \
  --extra-cflags=-I/opt/homebrew/include --extra-ldflags=-L/opt/homebrew/lib
make -j2
make install
```

이 실행 파일은 HEVC 검사에 필요한 최소 구성이다. 다른 코덱의 전체 workspace 검사에는 기존 외부 FFmpeg를 사용했다. 테스트 도구의 구성 차이와 실제 제품 코덱 실패를 구분한다.

## 실제 출력 8개 시나리오

별도 acceptance test 하나에서 8개 출력을 순차 검증했다. 각각 MP4/hvc1, 해상도·프레임 수·Main/Main 10·색 정보 및 외부 FFmpeg 전체 디코딩을 확인했다.

| 시나리오 | 프레임 | 소요 초 | 하드웨어 프레임 | 결과 |
| --- | --- | --- | --- | --- |
| auto-4k-pq | 4 | 6.181 | 4 | 통과 |
| auto-8k-pq | 2 | 16.460 | 2 | 통과 |
| injected-hardware-failure-pq | 8 | 2.412 | 0 | 통과 |
| software-4k-hlg | 4 | 3.596 | 0 | 통과 |
| software-4k-pq | 4 | 6.333 | 0 | 통과 |
| software-4k-sdr | 4 | 5.834 | 0 | 통과 |
| software-8k-pq | 2 | 8.349 | 0 | 통과 |
| software-8k-sdr | 2 | 6.586 | 0 | 통과 |

software는 하드웨어 팩토리를 등록하기 전 실행한다. 기존 H.265 계약은 `HardwareEncoding::Off`여도 등록된 하드웨어를 먼저 시도하므로 Off만으로 소프트웨어 경로를 증명할 수 없다. 첫 검사에서 이 잘못된 가정을 발견해 독립 소프트웨어 조건으로 수정하고 재실행했다.

실패 주입은 초기화 오류를 반환하는 팩토리를 등록하고, 뒤의 실제 VideoToolbox 팩토리는 비정사각 픽셀 설정으로 거절하게 한다. 오류 팩토리 호출 1회, 하드웨어 프레임 0개, 소프트웨어 8프레임 PQ 정상 파일을 확인했다. 인코딩 도중 GPU/드라이버 장애나 전원 차단의 복구 시험은 아니다.

PQ 파일에는 1000nit mastering display와 CLL SEI가 있다. 현재 `ColorSignal::static_metadata()`의 MaxCLL/MaxFALL 기본값 `(0,0)`을 확인했으며 실제 콘텐츠의 최대 밝기를 측정했다는 뜻은 아니다. 외부 Annex-B 추출로 소프트웨어 4K·8K의 모든 프레임이 16개 슬라이스임도 확인했다.

4K 4프레임·8K 2프레임의 짧은 OceanSunset 합성 씬이며 전체 출력 시간에는 렌더링·변환·인코딩·컨테이너 생성이 포함된다. 시작 비용과 시스템 부하의 영향이 크므로 하드웨어/소프트웨어의 일반적인 속도 순위나 장편 성능으로 해석하지 않는다.

## 압축 품질

외부 FFmpeg의 testsrc2 합성 영상, 1280×720, 24fps, 120프레임(5초), 8비트 SDR. IDR 48, 6개 슬라이스, 평균 비트레이트·최대 1.5배 ceiling을 사용했다. encode-only 시간은 원본 생성·I/O·입력 준비를 제외한다.

| 목표 kbps | 실제 kbps | 밝기 PSNR dB | 전체 SSIM | encode-only fps |
| --- | --- | --- | --- | --- |
| 1000 | 1019.86 | 34.61 | 0.961116 | 18.97 |
| 2000 | 2032.83 | 38.32 | 0.979392 | 20.19 |
| 4000 | 4053.93 | 44.07 | 0.992249 | 15.01 |

외부 FFmpeg로 디코딩한 모든 샘플의 SHA-256이 각 인코더 reconstruction과 일치했다. 이는 재구성의 정확성이고, 손실 압축 원본과 무손실로 같다는 뜻이 아니다. 같은 입력의 외부 x265 medium 참조는 약 2.20Mbps에서 밝기 PSNR 43.51dB·전체 SSIM 0.99436이었다. 실제 비트레이트·스레딩·구현이 달라 엄밀한 동일 조건 비교는 아니지만, 이번 샘플에서 자체 인코더의 압축 효율 개선 여지는 확인됐다.

합성 영상 하나의 결과이므로 실사·그레인·고속 운동·다종 카메라 원본 전체의 품질을 대표하지 않는다. x265는 외부 참조 도구로만 사용했다.

## 벤치마크 수정 및 재실행

기존 `tests/perf.rs`는 64행당 슬라이스 1개를 사용해 8K에서 68개였다. 제품은 128행당 1개, 최대16개다. 측정 설정을 제품 정책과 일치시킨 뒤 다음 결과를 얻었다.

| 영상 | 프레임 | 초 | fps |
| --- | --- | --- | --- |
| 1920×1080 8비트 | 30 | 9.22 | 3.25 |
| 3840×2160 10비트 | 8 | 10.21 | 0.78 |
| 7680×4320 8비트 | 3 | 11.87 | 0.25 |

이 테스트는 합성 프레임 생성도 포함하며 사용자 앱의 부하는 통제하지 않았다. 실시간/장편 처리 성능 보장이 아니다. 기존 README 성능 표는 과거 슬라이스 정책의 기록으로 보존했고 현재 측정과 구분했다.

## 회귀·품질 검사

- 인코더: 단위 15개·왕복 6개·외부 오라클 1개·문서 1개 통과.
- 디코더: 단위 43개 및 적합성 61개 통과. 적합성 타깃 기존 ignored 4개는 실행한 것으로 세지 않는다.
- 출력 모듈 단위 140개, 실제 VideoToolbox HDR 3개 통과.
- 명시 실행 품질 sweep 1개, 출력 행렬 1개(8개 시나리오), 수정된 perf 1개 통과.
- 전체 workspace Clippy(`--all-targets -- -D warnings`) 통과.
- 의존 계층 검사 통과, 자산 69개 attribution 검사 통과, WASM 50개 crate 검사 통과.
- 자산 검사 첫 실행은 PATH가 이 Mac에서 실행되지 않는 Git을 선택해 OS 오류 86으로 중단됐다. 제품 코드를 바꾸지 않고 native `/usr/bin/git`이 우선인 프로세스 PATH로 동일 검사를 재실행해 통과했다.
- `cargo test --locked --workspace --no-fail-fast`: 종료 0. 출력상 libtest/doctest 합계 **4,675 passed / 0 failed / 55 ignored**, 178개 결과 요약이다. 공유 레지스트리·카운터 검사의 격리를 위해 `RUST_TEST_THREADS=1`로 실행했다. 기존 optional fixture/self-skip와 compile-only 문서 테스트가 포함될 수 있으므로 모든 외부 코퍼스 본문을 실행했다는 뜻이 아니다. 별도 strict HEVC fuzz는 새 입력·스킵 0으로 위에서 구분했다.

처음 추가한 검사 파일의 if 서식으로 fmt가 실패한 기록도 남겼으며 rustfmt 적용 후 재검사 통과했다. 제품 오류를 숨기기 위해 기존 단언·ignore·테스트 조건을 제거하지 않았다.

## 재현

`filmcraft` 디렉터리에서 실행한다. 출력 폴더는 소스 저장소 밖의 절대 경로를 지정한다.

```sh
FILMCRAFT_REQUIRE_ORACLES=1 cargo test --locked --release -p filmcraft-hevcenc
FILMCRAFT_REQUIRE_ORACLES=1 cargo test --locked --release -p filmcraft-hevc --test it
FILMCRAFT_DELIVERY_DIR=/absolute/quality FILMCRAFT_REQUIRE_ORACLES=1 cargo test --locked --release -p filmcraft-hevcenc --test delivery_quality -- --ignored --nocapture
FILMCRAFT_DELIVERY_DIR=/absolute/delivery FILMCRAFT_REQUIRE_ORACLES=1 cargo test --locked --release -p filmcraft-platform --test hevc_delivery_validation -- --ignored --nocapture --test-threads=1
FILMCRAFT_REQUIRE_ORACLES=1 cargo test --locked --release -p filmcraft-platform --test videotoolbox_hevc_hdr_export -- --test-threads=1
cargo test --locked --release -p filmcraft-hevcenc --test perf -- --ignored --nocapture
```

`delivery_quality`는 원본·reconstruction·Annex-B와 PSNR/비트레이트 CSV를 남긴다. 외부 도구로 reconstruction과 디코딩 결과를 대조하고 원본과 SSIM을 추가 측정할 수 있다. 긴 검사는 비용·파일 출력을 명시하도록 ignored지만 이번에는 `--ignored`로 본문을 실행했다.

## 남은 한계

- 소프트웨어 출력은 4:2:0 8/10비트다. 4:2:2 확장은 입력 디코더이며 4:2:2 출력으로 안내하지 않는다.
- B프레임·디블로킹·SAO·RDOQ·2패스·CRF 등은 미지원이다.
- Windows/NVIDIA·Linux 실기, 실사 다종 코퍼스, 장편 8K 메모리/안정성은 미검증이다.
- 인코딩 중간 GPU/드라이버 장애 복구는 미검증이며 초기화 실패 fallback과 구분한다.
- 위 성능·품질 수치를 모든 장비·콘텐츠의 결과로 일반화하지 않는다.
