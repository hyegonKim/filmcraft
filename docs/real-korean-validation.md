# 실제 한국어 연속 발화 검증

빌드15 후속 검사는 마지막 절에 기록한다. 빌드13의 새 전체 전사와 빌드14 중간 결과는 당시 결과로 보존한다.

## 빌드 20261016.13 — 새 전체 전사

로컬 CPU Whisper-small로 실제 10분·60분 자료를 최종 서명 앱에서 각각 **처음부터 새로 전사**했다. 이전 프로젝트나 별도 단계의 전사 결과를 재사용하지 않았다. 두 설치 앱의 실행 코드 14개 섹션 일치와 서명을 검증했다. Adobe와의 품질 동등성을 측정한 결과는 아니다.

## 자료와 평가 범위

[OpenSLR 113 Seoul Corpus](https://openslr.org/113/)의 성인 면담 화자 `s12m23f` 600초와 `s13m26m` 3600초다. 실제 연속 녹음을 시간순으로 연결하고 자체 제작 단색 320×180, 24fps 화면을 결합했다. TTS·발화 반복·시간 늘리기를 사용하지 않았다. 원본 촬영 영상이나 4K 재생 성능 검사는 아니다.

사람이 교정한 정서법 전사와 TextGrid 단어 시각을 대조했다. 10분 178.158초, 60분 198.876초의 상대 화자·알 수 없는 발화는 평가에서 제외했다. CC BY-NC 2.0 음성·개별 전사·파생 미디어는 저장소와 앱 밖 `real-korean-validation/`에 보존한다. 두 자료는 오류 조사에 사용한 회귀 자료이며 미사용 평가 자료가 아니다.

## 변경과 원인

- 짧은 추임새가 인식돼도 양쪽 여백과 프레임 안쪽 반올림 때문에 삭제 후보가 사라졌다. 양쪽 인식 길이가 300ms 이하이고 양 끝 차이가 각각 40ms 이내인 경우에만 80ms 여백을 허용한다. 그 외에는 100ms와 기존 100/300ms 경계 일치 조건을 유지한다.
- 기본 2초 문맥에서 추임새가 누락된 경우에만 4초·1초 문맥을 시도한다. 대체 문맥에는 양쪽 일반 단어 일치가 필요하며, 추임새 경계가 충돌하면 다른 결과를 골라 통과시키지 않는다. 일반 단어와 겹치는 구간은 승인하지 않는다.
- 최소 200ms의 지속 음성, 75% 이상 활성 에너지, 음향 경계 60ms 보존을 추가 확인한다. 에너지는 발음·의미 판별이 아니다. 승인 정책 버전은 3이며 예전 승인은 새 전사 전까지 적용할 수 없다.
- 일반 단어가 긴 앞 발화를 흡수한 의심 구간은 무음 위치로 검사 대상을 제안한다. 별도 비유도 인식에서 전체 단어와 다음 일반 단어 두 개가 일치할 때만 경계를 줄인다. 단어·화자·개수는 유지하고, 0초 단어에 임의 시각을 만들지 않는다.
- 숨겨진 창의 논리 갱신이 입력을 소비하고 멈춘 UI 시계로 재시도를 기다리던 원인을 재현했다. 입력은 실제 화면 갱신까지 보존하고 backend 시계로 만료를 계산한다. 위젯 처리 후 응답한다. 검색 캐시와 첫 단어에서 종료하는 메뉴 상태 검사도 적용했다.

## 단어 경계와 전사 정확도

시간을 사용하지 않은 3단어 이상 연속 정답 블록에 조건부로 측정했다. 빌드7과 동일한 원시 단어 인덱스·제외 마스크를 고정해 비교했으며, 오차가 작은 단어만 선택하지 않았다.

| 10분 | 19.97% / 37.07% | 449 | 655 → 543ms | 270 → 270ms | 시작 10 / 0, 끝 악화 0 |

원시 단어열은 빌드7과 같으며 원문에 맞춘 치환은 넣지 않았다. CER/WER에 변화가 있으면 경계 보정으로 제외 영역에 포함되는 단어가 달라진 영향도 포함한다. 인식 오류·불확실 경계·0초 단어는 남아 있다. 이 검사는 전체 단어 경계 정확도나 음소 강제 정렬을 의미하지 않는다.

## 최종 앱의 전체 흐름

두 자료 모두 전사 자체 Undo/Redo, 선택 편집 Undo/Redo의 전체 프로젝트 일치, 저장/재열기 일치, 원본 SHA-256 불변, H.264/AAC 출력의 전체 디코딩·길이·프레임 수 검사를 통과했다. 마지막 페이지와 마지막 단어 표시, 추가 100회 탭 전환·페이지 이동도 검사했다.

|---|---:|---:|---|---|---|
| 10분 | 1560.16초 | 6,920 | 21.0 / 951.5ms | 599.541667초 / 14,389 | 824단어, 최소 상관 0.999473 |

전사 총시간에는 추가 단어·추임새 검사 CPU 인식이 포함된다. UI 수치는 전사·편집·출력 중 UI 스레드 요청 왕복 시간이며 OS 스케줄링도 포함한다. GPU 표시 프레임 지연이나 모든 환경의 무정지를 보장하지 않는다. 개발 중 빌드8/9/12의 입력 시간 초과는 실패로 남겼다. 숨겨진 갱신의 입력 소비·정지된 시계를 회귀 검사로 수정하고, 창 복원도 보강했다. 화면 캡처 성공 여부는 각 보고서의 screenshotError를 따른다.

독립 ffmpeg 디코더로 원본/출력 5개 구간과 사람 주석 일반 단어 각각을 대조했다. 60ms 이상·RMS 0.001 이상인 단어 전체에 24fps 삭제 경계가 정수 샘플인 48kHz에서 실제 삭제 시간을 적용하고, 평균 제거 파형 상관 0.9 이상·시차 ±3샘플(±62.5µs) 이내를 요구했다. 기존 16kHz의 ±1샘플과 같은 시간 허용치다. 한 단어에서 16kHz 소수 샘플 보간이 실패한 기록을 보존하고, 약 42µs 지연을 48kHz에서 맞춰 상관 0.9993으로 확인했다. 기준을 낮추지 않고 검사 정렬 방식을 수정해 두 자료 전체를 다시 검사했다. 주석 범위 밖 발화 보존을 증명하는 검사는 아니다.

## 재현 근거

저장소 밖 `real-korean-validation/final13-10min/`, `real-korean-validation/speaker13/final13-60min/`의 `report.json`, `accuracy.json`, `paired-boundary-check.json`, `audio-content-check.json`, `ordinary-word-audio-check.json`, `ui-latency.jsonl`과 프로젝트·MP4와 화면 캡처 성공/실패 기록을 보존했다. `v8/final13-validation-summary.json`, `v8/qa-bundle13.json`, `v8/installation.json`에 통합 수치와 바이너리·설치 근거를 기록했다.

음성 단위 40개, 프로젝트 호환 2개, 엔진 전사 18개 및 관련 UI·입력 회귀 검사를 통과했다. 이번 변경의 speech/UI clippy, 실제 배포 기능을 켠 앱 clippy(`whisper,macos-voices`, 경고 오류 처리), 최종 빌드와 fmt 검사도 통과했다. 창 숨김 해제·최소화 복원과 네이티브 창 정렬 요청 제한도 보강했다. 별도 실제 숨김·최소화 조작 검사는 CUA 선택 요청의 120초 시간 초과로 수행하지 못했으며 통과로 집계하지 않았다. 이전 빌드7의 후보 단계 재검사 결과와 구별하며, 이번 10/60분은 같은 최종 바이너리에서 새 전체 전사했다.

## 설치와 별도 시각 확인

두 설치 앱의 디스크 실행 파일은 빌드13으로 갱신됐다. 기본 `/Applications/FilmCraft.app`은
기존 실행 프로세스의 미저장 여부를 화면 제어 도구로 확인하지 못해 종료하지 않았다.
작업을 저장하고 재실행해야 새 빌드가 로드된다. 개발판 `~/Applications/FilmCraft Korean.app`은
정상 종료·재실행 후 기본 데모 화면을 확인했다. 기존 테스트 복구 기록은 Not Now로 보존했다.

긴 두 전사 실행의 `screenshotError`는 실패로 유지했다. 이후 같은 최종 앱에 창 포커스를
명시적으로 주고 저장된 결과를 각각 다시 열어 전사·후보 검토 화면을 캡처했다.
`visual13/`과 `visual13-60/`에 캡처가 있다. 불확실 후보의 비활성 체크와 자동 선택 없음도
확인했다. 60분은 마지막 페이지 14/14·전체 6,701단어이고, 추가 스크롤 후 마지막 단어
인덱스 6700의 화면 표시를 `visual13-bottom/last-word-60min.png`와 요소 좌표로 확인했다.
이 추가 시각 검사는 새 전사를 대체하지 않으며 원래 두 전사의 시간·성공/실패 기록을 바꾸지 않는다.

개발판의 네이티브 파일 열기 자동화에서는 `+[NSOpenPanel openPanel]`의 NULL 반환이
UI 오류 경계에 잡힌 사례가 있었다. 앱은 종료되지 않았고 Escape/Continue로 데모 화면을
유지했다. 이 파일 선택기 동작을 통과로 집계하지 않는다. 직접 경로 `file.open`으로 실제
전사 프로젝트를 다시 여는 경로는 통과했다. 이후 `interactive` 모드에서 실제 네이티브 포커스가 true인 전경 상태를 확인하고,
네이티브 Open Project 선택기로 같은 실제 프로젝트를 열었다. 저장한 사본의 전체 프로젝트가
원본과 정확히 일치했다(`picker13/report.json`). 전경 파일 열기는 통과했으며, 앞선
백그라운드 자동화 실패는 구분해 보존한다. 백그라운드 파일 선택기·모든 OS UI 상태까지
해결했다는 결과는 아니다.

일반 단어 오디오 검사는 저장소의 `scripts/verify_real_korean_word_audio.py`로 재현한다.
`verify_real_korean.py`의 최종 새 전사 실행은 `--reuse-project`를 사용하지 않아야 한다.


## 빌드 20261018.14 — 단어 끝·추임새·트랙 보호 후속 검사

빌드14 검사는 완료했으며 기본 설치 앱에는 반영하지 않았다. 재현율이 증가하지 않아
원인을 추가 진단하고 후속 빌드15를 검사 중이다.

이번 검사는 빌드13의 한국어 10/60분 주 전사 텍스트와 검증된 시작 시각을 유지하고,
실제 원본 오디오에서 새 단어 끝 검사와 추임새 문맥 재인식을 수행한다.
전체 10/60분 주 전사를 새로 실행했다는 결과가 아니다. 사람 주석은 결과 평가와
다른 발화가 겹치는 QA 트랙 구성에만 사용하며 인식·보정 코드에는 제공하지 않는다.
같은 회귀 자료이므로 미사용 화자 일반화 평가가 아니다.

10분 자료의 고정 449개 일치 단어에서 끝 경계 오차 p95가 269.864 → 231.282ms로
줄었다. 끝 시각 2개가 100ms 이상 개선됐고 100ms 이상 악화나 새 조기 종료는 0개다.
모델 attention 종료가 마지막 발음보다 빠른 사례를 발견해, 어휘 확인과 별도로
전체 음향 prefix 및 60ms 여백을 보존하도록 수정했다. 시작 시각·텍스트는 유지했다.
추임새 승인은 2/14(14.29%)로 이전과 같다. 승인 어휘 오탐과 일반 단어 침범은 0이며,
10분 재현율이 향상됐다고 주장하지 않는다.

기존 설치 빌드가 윗 트랙의 `음`을 자르면서 1.25초 다른 source offset의 아랫 트랙
일반 단어 `성별은·남자고요`를 함께 자르는 오류를 실제 파일로 재현했다.
빌드14에서는 미리보기·선택 적용·기존 무음/추임새 제거 명령이 공통 보호 검사를 쓴다.
잠긴 오디오·비디오·자막의 후속 구간과 다른 매핑의 중첩 오디오는 적용 전에 차단한다.
같은 파일이어도 stream/channel/effects/speed/source mapping이 다르면 복제로 간주하지 않는다.
자동 기본-stream 한국어 전사는 custom stream/channel 클립 편집을 허용하지 않는다.
채널별 새 ASR을 구현했다는 뜻은 아니다.

10분 네이티브 앱 검사에서 잠긴 A1/V1, 다른 발화 A2, custom channel을 차단했고,
거부 전후 프로젝트와 저장·재열기가 정확히 같았다. 두 발화가 겹치는 구간의 거부 전후
출력 WAV도 동일하며 독립 원본 합산 신호와 상관 0.999999992다.
동기화된 A1/A2 복제, 빈 잠금 A3, 컷 이전 별도 A4 조합은 편집을 허용하고 매핑 정렬,
A4 불변, 전체 프로젝트 Undo/Redo·저장·재열기를 검증했다.
